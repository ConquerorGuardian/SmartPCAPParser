# Как устроено приложение

Документ для тех, кто будет читать код: что где лежит, почему сделано так и
куда добавлять новое.

## Поток данных

```
фраза на русском
      │
      ▼
parser/engine.py        разбор фразы: намерение + сущности (ip, порт, протокол,
      │                 mac, домен, направление, отрицание)
      ▼
parser/filters.py       сущности → строка display filter Wireshark
      │
      ▼
parser/matcher.py       парсер и вычислитель этого фильтра на пакетах
      │                 (если ввели готовый фильтр Wireshark — он идёт сюда же)
      ▼
parser/pcap_handler.py  применение фильтра к списку пакетов, лимит строк,
      │                 подготовка страниц для таблицы
      ▼
gui/                    таблица, детали, потоки, статистика, вердикт
```

Чтение файла идёт параллельно: `parser/pcap_reader.py` разбирает кадры,
`parser/pcap_handler.py` складывает их в список `Packet`, интерфейс
показывает прогресс.

## Модули

| Модуль | Ответственность |
| --- | --- |
| `parser/pcap_reader.py` | pcap и pcapng: заголовки, интерфейсы, linktype, Ethernet/VLAN/IP/ TCP/UDP/ICMP/ARP, TLS/HTTP/DNS из данных, таймстемпы |
| `parser/engine.py` | словарь протоколов и групп, разбор фраз, нормализация падежей, отрицания, направления, «сырой» фильтр Wireshark |
| `parser/filters.py` | сборка display filter из сущностей; имена сайтов через `http.host`/`tls.sni`/`dns.qry.name` |
| `parser/matcher.py` | парсер и вычислитель фильтров: `and`/`or`/`not`, сравнения, `in {…}`, `contains`, протоколы |
| `parser/pcap_handler.py` | загрузка файла с прогрессом и отменой, применение фильтра, страницы, лимиты |
| `parser/streams.py` | поток TCP (реконструкция по seq, оба направления) и обмен UDP |
| `parser/stats.py` | график по времени, иерархия протоколов, разговоры, узлы, сайты |
| `parser/verdict.py` | разбор файла простыми словами и находки |
| `parser/settings.py` | `~/.smartpcapapp/settings.json`: тема, окно, история, недавние |
| `gui/app.py` | ядро окна: загрузка, команды, тема, настройки, статусы |
| `gui/layout.py` | построение виджетов и сетки |
| `gui/table_view.py` | таблица: сортировка, поиск, страницы, контекстное меню |
| `gui/stats_view.py`, `gui/chart.py` | вкладка статистики и график |
| `gui/dialogs.py`, `gui/help_text.py` | справка, детали, поток, вердикт, тексты |
| `main.py` | точка входа: GUI, консольные режимы, `--selftest`, `--version` |

## Ключевые решения и почему так

**Только стандартная библиотека.** Ни `scapy`, ни `pyshark`, ни `dpkt`.
Причина: exe не должен тянуть tshark и десятки мегабайт зависимостей; парсер
нужен ровно для тех протоколов, которые показываются. Внешняя зависимость
одна — `customtkinter` (интерфейс).

**Свой вычислитель фильтров.** Сгенерированный фильтр нужно не только
показать, но и применить к пакетам без Wireshark. Поэтому `matcher.py`
разбирает подмножество синтаксиса Wireshark и считает предикат на `Packet`.
Неизвестное поле → понятная ошибка со списком поддерживаемых, а не тихое
«0 пакетов».

**Заголовки в памяти, тела — по требованию.** Все пакеты читаются целиком
(структура `Packet`), но payload хранится только до порога (25 МБ файл,
64 МБ на поток). Это даёт быстрый старт на больших дампах и предсказуемую
память.

**Русский интерфейс как первый класс.** Движок сравнивает слова по общему
началу, чтобы работали падежи и разговорные формы («телефонию», «шару»,
«айпишник»). Словарь протоколов — данные, а не код: добавить протокол —
несколько строк в `PROTOCOL_FILTERS`.

**Ничего не пишем в реестр и рядом с exe.** Настройки — в домашней папке,
отчёт самопроверки — в `%TEMP%`. Exe можно запускать с флешки и из
`Program Files` без прав администратора.

**Один файл, один тег, один релиз.** `tools/build_exe.py` собирает onefile и
onedir, пишет `SHA256SUMS.txt`, CI проверяет обе сборки и прикрепляет их к
релизу. Версия объявлена в одном месте — `parser/__init__.py`.

## Как добавить протокол

```python
# parser/engine.py
PROTOCOL_FILTERS = {
    ...,
    "mongodb": ["mongodb", "монго", "mongo"],
}
```

Фильтр для Wireshark — имя протокола (`mongo`). Не забудьте:

- `parser/matcher.py` — имя в `PROTOCOL_NAMES`, если оно отличается от
  отображаемого (`netbios` → `nbns`);
- `tests/test_engine.py` — фраза даёт ожидаемый фильтр;
- `docs/EXAMPLES.md` и `gui/help_text.py` — чтобы о протоколе узнали.

## Тесты

```
tests/
├── run_all.py            раннер: собирает модули по списку
├── test_engine.py        фразы → фильтры, словарь, падежи
├── test_reader.py        pcap/pcapng, битые файлы, linktype
├── test_matcher.py       вычислитель: поля, операторы, ошибки
├── test_handler.py       загрузка, фильтрация, лимиты
├── test_streams.py       TCP-поток, UDP-обмен
├── test_stats.py         агрегаты статистики
├── test_verdict.py       находки вердикта
├── test_settings.py      сохранение и загрузка настроек
├── test_golden.py        CLI: --version, --selftest, файл аргументом
├── test_corpus.py        реальные дампы (если скачаны)
├── test_full_pipeline.py весь путь: файл → фильтр → таблица
└── test_gui_smoke.py     окно: загрузка, команды, темы, закрытие
```

Правило: тест не требует сети и не оставляет файлов в проекте (временные —
в `%TEMP%` или `tests/_*`, они в `.gitignore`).

## Производительность

`tools/bench.py` генерирует дамп нужного размера и печатает тайминги.
Ориентиры на обычном ноутбуке: 13-пакетный пример — мгновенно, 40 МБ
(~237 000 пакетов) — секунды на чтение, фильтр — доли секунды. Узкие места
при профилировании: разбор TLS/HTTP из payload и реконструкция TCP-потока.
