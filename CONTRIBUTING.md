# Участие в проекте

Ошибка, идея, новый протокол в словаре, опечатка в справке: всё полезно.
Проект маленький, любая правка заметна.

## Запустить у себя

```bash
git clone https://github.com/Whitemoneydealer/SmartPCAPParser.git
cd SmartPCAPParser
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
python main.py
```

Нужен Python 3.11 или новее, проверял на 3.13. Единственная зависимость для
работы это `customtkinter`, остальное стандартная библиотека. Так и задумано:
программа должна запускаться на машине, где ничего не установлено.

## Тесты

```bash
python -m tests.run_all      # все модули
python -m tests.test_engine  # один модуль
pytest -q                    # то же через pytest
```

Тесты это обычные функции `test_*` с `assert` и печатью `PASS:`. Раннер
`tests/run_all.py` идёт по списку в конце модуля, поэтому новый тест нужно
дописать в список `tests = [...]`, иначе он просто не запустится.

## Линтер

```bash
ruff check .
```

Строки до 100 символов. Идентификаторы по-английски, комментарии и тексты
интерфейса по-русски. Новые зависимости в `requirements.txt` не добавляем без
причины: каждая лишняя библиотека это ещё несколько мегабайт в exe.

Парсер не доверяет файлу. Любые длины и смещения проверяем, исключения
ловим, на битом дампе приложение не падает. Сообщения для пользователя
пишем так, чтобы было понятно, что делать, а не просто «ошибка».

`ruff format` я не применяю: в коде осмысленные переносы. Новый код лучше
держать в том же духе.

## Сборка

```bash
python tools/build_exe.py --both
python tools/check_exe.py dist/SmartPCAPParser.exe dist/SmartPCAPParser/SmartPCAPParser.exe
```

Иконка перерисовывается `python tools/make_icon.py` (нужен Pillow),
резервная копия проекта делается `python tools/backup.py --note "..."`.

## Где можно помочь

1. Словарь протоколов. Новый протокол это несколько строк в
   `PROTOCOL_FILTERS` в `parser/engine.py`, группа в `PROTOCOL_GROUPS` и тест
   в `tests/test_engine.py`.
2. Тексты справки. `gui/help_text.py` и `docs/EXAMPLES.md` читают первыми,
   там всегда есть что улучшить.
3. Новое поле фильтра в `parser/matcher.py`, например `ip.dsfield`, плюс
   тест в `tests/test_matcher.py`.
4. Эвристики вердикта в `parser/verdict.py`: подозрительные домены, скан
   портов, аномалии. Нужны тесты на синтетических дампах.
5. Скорость. `tools/bench.py` и профилирование на дампах от 100 МБ.

## Pull request

Одна задача, одна ветка от `main`. Тесты и `ruff check .` должны проходить,
CI всё равно проверит. Если меняется поведение, обновите `CHANGELOG.md`, а
при необходимости README и `docs/`.

В описании напишите, что было и что стало, как это проверить. Для интерфейса
приложите скриншот до и после.

Коммит: короткая строка в повелительном наклонении, по-русски или
по-английски. Тело добавьте, если нужно объяснить причину, а не пересказать
диф.

## Баг-репорт

Хватит шагов, ожидаемого и фактического поведения, версии приложения
(`--version`) и версии Windows. Дамп прикладывайте, если в нём нет чужих
данных. Если есть, соберите маленький пример на `tests/generate_sample_pcap.py`.

Уязвимости обсуждаются отдельно, см. [SECURITY.md](SECURITY.md).
